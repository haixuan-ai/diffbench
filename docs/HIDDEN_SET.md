# Hidden set: commit–reveal

`spec.hidden_variants(seed)` deterministically perturbs masses, friction, initial speeds, heights, rod length, incline angle and stack height of the public scenarios (same truth functions, ids end in `~h`).

1. Organizers publish `sha256(seed)` (the commitment) and the evaluation window **before** the window opens.
2. Entrants run during the window with only the commitment known.
3. After the window the seed is published. Anyone checks `sha256(seed)` against the commitment and re-runs: `python -m diffbench.runner --engines ... --hidden-seed <seed>`.
4. Bundles with `track = accuracy_hidden` store the commitment (`hidden_seed_commitment`).

**Status of the v0.1 release.** The one hidden-set run we published (Nexus ×2 and MuJoCo) used the demo seed `demo-seed-2026` that was known to the developers of the engine under test, so it is **not** a formal commit–reveal result. It shows that engine fixes did not only fit the public scenarios; it does not prove generalization. A formal window with a seed generated by a neutral party is a release gate (see `docs/RELEASE_PLAN.md` in the release folder).
