# 协议（Protocol B：参数对齐，各引擎使用自身默认数值配置）

1. 场景规格：`diffbench/spec.py`（z-up，SI，四元数 wxyz），其哈希写入每个结果包。
2. 对齐项：几何、质量、(对称)转动惯量由几何推出、滑动摩擦系数 μ、重力、时间步长 dt。
   不使用恢复系数；不设置滚动/扭转摩擦。各引擎的摩擦组合规则不同时，适配器把"有效 μ"对齐为场景 μ，并在适配器源码中注明。
3. 不对齐项（刻意）：积分器、接触模型与求解器参数一律取各引擎默认值，不针对场景调参；配置写入结果 `config` 字段。
4. 状态读取：质心位置、体姿态、质心线速度、世界系角速度；先 forward 再读。适配器的坐标/约定错误用 free_fall / projectile_spin 两个无接触场景暴露并修正，禁止通过分数反推调参。
5. 真值：自由落体/抛射/滑行/斜面/滚动为闭式解；无力矩刚体与复摆为 RK4（h≤1e-4）高精度数值解。
6. 指标逐项报告并对照场景公开容差；没有综合分。失败、NaN、不支持如实记录为 error。
7. 速度（steps/s）仅作参考：单环境 CPU，含绑定开销；GPU 引擎不在设计工况。
8. 已知限制：已知的引擎局限（如 MuJoCo 默认 Euler 积分的位置一阶误差）会表现为真实误差，不做修饰；Nexus 的两套求解器分别参赛。
